# Stage A4 — file-set contracts, generated artifacts and composite presets

Stage A4 extracts the next generic verification primitives from the the original production consumer reference consumer while keeping the portable engine consumer-neutral.

## File-set suites

A suite may declare `fileSet`. The command is executed once per matched file using `{file}` (project-relative) or `{file_abs}` (absolute). The first failing item stops the set, preserving simple cancellation/process supervision semantics.

```json
{
  "argv": ["php", "-l", "{file_abs}"],
  "fileSet": {
    "patterns": ["backend/**/*.php", "public/**/*.php"],
    "exclude": ["vendor/**"],
    "allowEmpty": false,
    "perFileTimeoutSeconds": 30
  },
  "tool": "php",
  "resultAdapter": "exit-code"
}
```

The implementation is deliberately serial in A4. This keeps process-tree cancellation exact and the runtime small. Parallel file-set execution is an optimization to add only with equally correct multi-process supervision.

## Preconditions and output contracts

`requires` is a cheap precondition. Every pattern must resolve before the command is launched.

`outputs.required` is a postcondition. `outputs.capture` records exact SHA-256 hashes of generated files. Ordinary cache reuse is rejected if required output disappears or captured bytes no longer match the stored PASS result.

```json
{
  "requires": ["frontend/package.json"],
  "outputs": {
    "required": ["frontend/dist/index.html"],
    "capture": ["frontend/dist/index.html", "frontend/dist/assets/**"]
  }
}
```

This is the portable primitive behind the reference rule that a reused Vite result is trustworthy only when current generated bytes exactly match the certified generated bytes.

## Composite presets

Complex presets no longer need to copy the command/policy graph of their parts. A top-level preset may list `components`; component JSON is merged deterministically:

- objects merge recursively;
- arrays append unique values in first-seen order;
- later scalar values replace earlier ones.

Components are data under `presets/components/`, not executable plugins. Cycles are rejected.

`php-vue-vite` is now only:

```json
{
  "components": ["php-backend", "vue-vite-frontend"],
  "files": {}
}
```

The two atomic components themselves share a small `base` component. This removes the duplicated suite/policy graph while preserving a fully materialized ordinary `agent-tools.json` and `agent-check.policy.json` when the preset is applied.

## Self-hosting

Agent DevTools remains its own first consumer. Stage A4 qualification executes the portable full check against this repository itself, first cold and then warm. Unit/integration tests exercised by that self-check cover preset composition, file-set execution, precondition failure and generated-byte cache invalidation.

Release and Context are marked not self-hosted until those facades exist; self-hosting is expanded feature-by-feature rather than simulated.
