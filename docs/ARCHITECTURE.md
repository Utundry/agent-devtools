# Architecture

## Shape

```text
project/
├─ devtools/agent/ or vendored equivalent
├─ agent-tools.json              # optional project adapter/config
├─ source/tests/docs/...
├─ .agent-cache/                 # ignored, disposable
└─ .agent-work/                  # ignored, disposable
```

Portable internals should remain small and composable:

```text
agent_devtools/
├─ core/
│  ├─ fingerprint
│  ├─ paths/discovery
│  ├─ process
│  ├─ manifest
│  ├─ evidence/cache
│  └─ report
├─ check/
├─ release/
└─ context/
```

The physical modules may evolve, but the dependency direction is strict: facades depend on the small core; project adapters depend on public facade/core contracts; the portable core must not import consumer-project modules.

## Shared primitive

All reusable evidence should be keyed from deterministic inputs rather than project-wide timestamps:

```text
artifact key =
    engine/schema version
  + configuration fingerprint
  + relevant input fingerprints
  + required tool/environment identity
```

This is the central pattern already proven by the donor incremental certification implementation.

## Optional integrations

Git, FTS5, project impact graphs and language recognizers are capabilities, not mandatory infrastructure. Missing optional capabilities must degrade safely:

- no Git -> basic query/full checks still work; affected mode can fail safe to full;
- no FTS5 -> lexical Python fallback;
- no explicit semantic anchors -> natural symbols/headings/generic chunks;
- unknown file/language -> generic text handling or conservative verification.

## Cache isolation

Prefer separate disposable stores (`check.sqlite`, `context.sqlite`) rather than one coupled database. Shared algorithms do not require shared persistence.

## Declarative consumer surface

Framework knowledge belongs in `agent-tools.json`, check policy and optional preset JSON. The runner provides only small generic primitives such as command execution, project-relative cwd/env, result adapters, fingerprints and evidence. Presets are templates for those declarations; they are not plugin code.

A result adapter is part of the verification contract and therefore part of the cache identity. This avoids reusing PASS evidence after changing what “PASS” means.

## A4 suite contracts

Portable suites may add three generic contracts without framework-specific engine code:

- `requires`: project-relative path/glob preconditions;
- `fileSet`: execute the same managed command per matched source file;
- `outputs.required` + `outputs.capture`: postconditions plus exact generated-byte evidence.

Captured output hashes are part of cached PASS result validation. A matching command/input key is insufficient when generated bytes have disappeared or changed.

## Preset composition boundary

Preset components are static JSON fragments, not a plugin system. Complex presets materialize to ordinary consumer configuration before the check engine sees them. This keeps composition out of runtime verification semantics and follows DRY without introducing dynamic loading.


## Certified evidence boundary

Ordinary check cache and certified PASS evidence are separate stores. Certified evidence is keyed by declared inputs plus execution/tool/engine identity and is promoted only when the entire certification run passes. File-set suites may reuse per-file evidence. Exact replay is a separate reproducibility layer: a deterministic binary-safe source delta bundle validates its base before applying and may cold-certify the reconstructed tree plus compare captured generated bytes. Release packaging reuses this layer instead of reimplementing it.


## Release-core boundary

The release facade is a thin composition layer over Check/Replay rather than an independent verifier. It freezes package inventories only after replay/certification has produced required build outputs. Package definitions are declarative (`source` or generic `files`). Artifacts are assembled in a sibling staging directory, verified from their own manifests/evidence, and only then atomically renamed into the requested output directory. Deployment-provider actions remain outside mandatory core.
