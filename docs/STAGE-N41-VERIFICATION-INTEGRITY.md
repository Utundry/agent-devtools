# Stage N4.1 — Verification Integrity

This skeptic-hardening slice closes two verification gaps found by auditing the public 0.8.10 release.

## CI parity

GitHub CI now runs the complete stdlib test discovery command used by release qualification:

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

The CI contract no longer depends on a manually maintained subset of test modules that can omit newer regression suites.

## File-set certified output integrity

Granular `fileSet` evidence is valid only for the individual file executions it records. A captured generated artifact belongs to the completed file-set suite as a whole.

For reusable file-set suites with `outputs.capture`:

1. per-file evidence remains content-addressed and reusable;
2. the completed suite also records suite-level output evidence keyed by the complete suite input fingerprint;
3. warm certification may reuse per-file evidence only when the current captured bytes match that complete suite evidence;
4. if complete output evidence is absent or the generated bytes changed, all file-set items execute again before a new suite-level output fact is promoted;
5. queued evidence is still promoted only after the complete certification run passes.

This prevents stale or manually modified generated output from being accepted as a fresh PASS merely because every per-file input is unchanged.
