# Stage A — extract portable Agent Check with behavioral parity

## Goal

Turn the proven the original production consumer Agent Check into reusable `agent check` machinery without changing its verified semantics first.

## Rule

**Extract before redesign.** The original reference implementation was the behavioral oracle during Stage A extraction; it is not distributed in the public repository.

## Stage A6 status — complete

The extracted portable surface now includes:

- portable named-feature policy engine and transitive impact expansion;
- compatibility loading for the certified the original production consumer policy format;
- declarative consumer safety guards for full fallback, test/runner boundaries and suite dependencies;
- managed subprocess execution with direct-to-file logs, bounded diagnostic tail and process-tree timeout handling;
- content-addressed ordinary development cache;
- structured result adapters, project-relative cwd/env and lightweight placeholders;
- generic file-set execution, required-path preconditions and generated-output SHA-256 contracts;
- DRY preset component composition without runtime plugin logic;
- separate transactional certified PASS evidence and `certify --cold`;
- per-file certified reuse for file-set checks;
- automatic verifier-engine identity in cache/evidence keys;
- deterministic binary-safe exact replay from a directory/ZIP base without requiring Git;
- pre-apply base fingerprint validation and per-payload SHA-256 validation;
- target incremental certification + replay cold certification;
- exact canonical source equality and declared generated-output equality;
- self-host qualification of check, certification, preset composition and exact replay.

The portable core imports no consumer module. consumer-specific suites, paths and acceptance details remain fixture/reference data.

## Stage A acceptance

Stage A is accepted when qualification confirms:

- deterministic affected selection and explain output;
- unknown/global fail-safe behavior;
- managed subprocess timeout/cancel/process-tree handling;
- bounded diagnostics and full file logs;
- abnormal structured completion cannot become PASS;
- certified evidence remains distinct from ordinary development cache;
- group/file-scoped evidence behaves deterministically;
- generated bytes are revalidated before evidence reuse;
- `certify --cold` is a physical control path;
- exact replay reconstructs canonical source and generated bytes;
- no silent mutation of version/release metadata/tests/source is used to obtain PASS.

## Explicitly outside Stage A

- release packaging/deployment providers;
- embeddings or context search;
- broad plugin framework;
- server/UI;
- rewriting reference code for elegance;
- changing consumer verification policy.
